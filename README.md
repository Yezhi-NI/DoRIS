# DoRIS

**DoRIS** — библиотека для 1С:Предприятие, предназначенная для распознавания документов с помощью внешних OCR-сервисов и преобразования результатов распознавания в универсальную структуру данных, пригодную для дальнейшей обработки в 1С.

Проект отделяет работу с конкретным OCR API от обработки документа: разные OCR-провайдеры приводят свои результаты к общей промежуточной модели, после чего DoRIS формирует единое представление документа.

## Возможности

* распознавание PDF и изображений;
* поддержка нескольких OCR-провайдеров;
* единый интерфейс независимо от используемого OCR API;
* извлечение обычного текста документа;
* распознавание и нормализация табличных данных;
* преобразование результата OCR в универсальную структуру `Document`;
* возможность дальнейшего заполнения документов 1С;
* обработка нескольких файлов за один вызов.

В версии **0.1 beta** поддерживаются:

* **PaddleOCR Cloud API**
* **Mistral OCR API**

Архитектура позволяет добавлять другие OCR-провайдеры без изменения основной логики обработки документов.

## Как это работает

Клиент передает DoRIS один или несколько файлов.

Для каждого файла библиотека:

1. определяет настроенный OCR-провайдер;
2. отправляет файл в соответствующий OCR API;
3. получает и разбирает результат распознавания;
4. приводит данные разных OCR-провайдеров к общей промежуточной модели;
5. нормализует текст и таблицы документа;
6. формирует универсальную структуру `Document`;
7. возвращает результат клиентскому коду либо использует его для заполнения объекта 1С.

Общий pipeline:

```text
Клиент 1С
    │
    ▼
DoRIS
    │
    ▼
выбор OCR-провайдера
    │
    ├──── PaddleOCR
    │
    └──── Mistral OCR
             │
             ▼
          OCR API
             │
             ▼
       результат OCR
             │
             ▼
   промежуточная OCR-модель
             │
             ▼
     обработка документа
             │
             ├── текст
             └── таблицы
             │
             ▼
          Document
             │
       ┌─────┴─────┐
       ▼           ▼
  клиент 1С    документ 1С
```

## Модель данных

DoRIS использует два основных уровня представления распознанных данных.

### OCR-модель

Каждый OCR-провайдер самостоятельно обрабатывает формат своего API и приводит результат к общей промежуточной модели.

Упрощенно:

```text
ДокументOCR
├── СтрокиДокумента
└── ТаблицыТоваров
```

Благодаря этому основная логика DoRIS не зависит от формата JSON конкретного OCR-сервиса.

### Document

После обработки OCR-модели создается универсальная структура:

```text
Document
├── ТипОбъекта
├── ТипДокумента
├── МассивСтрок
├── РеквизитыДокумента
└── ТабличнаяЧасть
```

`Document` является основным результатом обработки документа внутри DoRIS.

Он отделяет распознавание документа от логики конкретной конфигурации 1С.

## Обработка таблиц

OCR-сервисы могут возвращать таблицы с различным физическим представлением колонок и ячеек.

DoRIS выполняет дополнительную нормализацию таблиц:

```text
OCR-таблица
    │
    ▼
определение структуры колонок
    │
    ▼
нормализация строк
    │
    ▼
логическая таблица
    │
    ▼
Document.ТабличнаяЧасть
```

Это позволяет обрабатывать в том числе таблицы, разделенные между несколькими страницами документа, и некоторые случаи, когда одна логическая колонка представлена OCR несколькими физическими значениями.

## OCR-провайдеры

### PaddleOCR

DoRIS поддерживает работу с PaddleOCR Cloud API.

Для PaddleOCR используется асинхронная схема:

```text
файл
  │
  ▼
создание задания
  │
  ▼
JobID
  │
  ▼
ожидание результата
  │
  ▼
OCR JSON
```

### Mistral OCR

Mistral OCR получает документ непосредственно через API и возвращает результат распознавания без отдельного цикла обработки задания со стороны DoRIS.

```text
файл
  │
  ▼
Mistral OCR API
  │
  ▼
OCR JSON
```

Независимо от различий API оба провайдера формируют одинаковую промежуточную модель для дальнейшей обработки.

## Добавление OCR-провайдера

Архитектура DoRIS предполагает возможность подключения дополнительных OCR-сервисов.

Новый провайдер должен:

```text
файл
 │
 ▼
OCR API
 │
 ▼
ответ конкретного провайдера
 │
 ▼
общая OCR-модель DoRIS
 │
 ▼
Document
```

Таким образом особенности API конкретного сервиса остаются внутри реализации провайдера, а остальная часть библиотеки продолжает работать с общей моделью данных.
